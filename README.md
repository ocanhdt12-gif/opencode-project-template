## Overview

This template provides a **multi-agent workflow** for building web applications. Instead of manually managing tasks and phases, specialized AI agents collaborate to take your project from brief to deployment.

**Key features:**
- 📝 **Brief-first workflow** — start with a simple BRIEF.md, agents handle the rest
- 🤖 **Model-agnostic** — works with any AI tool (Cursor, Opencode, Windsurf, GitHub Copilot)
- 🔄 **Resumable** — pause and resume anytime, progress is saved in `.context/`
- 🧠 **Error memory** — agents learn from mistakes, avoid repeating them
- 🔍 **Independent review** — separate model reviews code to eliminate bias
- 🚀 **Automated DevOps** — git setup, CI/CD, and deployment handled by DevOps agent

---

## Architecture

This template combines **4 architectural patterns**:

| Pattern | Role |
|---------|------|
| **Event-Driven** | Classify intent, route to correct agent |
| **Graph** | Dependency-driven layer breakdown (Layer 0 → 1 → 2 → ...) |
| **Loop (ReAct)** | Execute tasks, test, fix, retry until passing |
| **Blackboard** | Shared state in `.context/` — enables pause/resume |

## How It Works

### Full Pipeline

```
BRIEF.md
    │
    ▼
Brainstorm Agent
├─ Gather requirements (one question at a time)
├─ Git setup (platform + token instructions)
├─ Model selection (reads from your AI tool config)
└─ Save .context/brainstorm-log.md
    │
    ▼
Spec Validator (different model)
├─ Check BRIEF + brainstorm-log vs SPEC
├─ FAIL → Brainstorm fills gaps
└─ PASS → continue
    │
    ▼
Graph Agent → Break into dependency layers
    │
    ▼
┌──────── For each Layer N ────────┐
│                                   │
│  Loop Agent:                      │
│  ├─ Execute tasks                 │
│  ├─ Test FAIL → Error Analyzer    │
│  │    → fix → retry               │
│  └─ Test PASS → git commit        │
│       (rollback point)            │
│                                   │
│  Review Agent (different model):  │
│  ├─ FAIL → fix + log error memory │
│  └─ PASS → DoD checklist ✅       │
│                                   │
└──────────────────────────────────┘
    │
    ▼
👀 Human Checkpoint
"Layer N done — proceed to next layer?"
    │
    ▼
DevOps Agent
├─ Run CI (lint + test + build)
├─ Deploy to staging
├─ Human approves → deploy production
└─ Health check / auto-rollback on failure
    │
    ▼
Done ✅ → Extract patterns → Update common-errors.md
```

## Agent Roles

| Agent | File | Description |
|-------|------|-------------|
| **Brainstorm** | `.agent/brainstorm.md` | Gathers requirements via interactive Q&A |
| **Spec Validator** | `.agent/spec-validator.md` | Validates spec completeness using a different model |
| **Graph Planner** | `.agent/graph.md` | Decomposes project into dependency-ordered layers |
| **Loop Builder** | `.agent/loop.md` | Implements tasks using ReAct (read → plan → code → test → fix) |
| **Blackboard** | `.agent/blackboard.md` | Maintains shared state; enables pause/resume |
| **Reviewer** | `.agent/reviewer.md` | Independent code review with a different model |
| **Error Analyzer** | `.agent/error-analyzer.md` | Root cause analysis; builds error memory to prevent recurrence |
| **Context Manager** | `.agent/context-manager.md` | Summarizes and pins context to prevent amnesia in long sessions |
| **Rollback** | `.agent/rollback.md` | Git commit strategy; reverts layer on failure |
| **DevOps** | `.agent/devops.md` | Git init, CI/CD pipeline, staging/production deployments |
| **Change Request** | `.agent/change-request.md` | Handles feature additions, modifications, or removals post-launch |

## Change Requests

After the project is complete, use the **Change Request Agent** for modifications:

### ADDITIVE — Add a new feature
```
User: "Add Excel export feature"
→ Change Request Agent analyzes impact
→ Spec Validator validates updated SPEC
→ Graph creates new layer/tasks
→ Loop → Review → DevOps (normal flow)
```

### MODIFY — Update existing feature
```
User: "Change order status flow"
→ Identify affected tasks
→ Re-run Loop for those tasks
→ Review + DevOps
```

### REMOVE — Remove a feature
```
User: "Remove Stripe payment"
→ Mark deprecated in SPEC
→ Create cleanup tasks
→ Review + DevOps
```

SPECIFICATIONS.md is automatically versioned:
```markdown
## Changelog
- v1.0: Initial spec
- v1.1: Add Excel export
- v1.2: Remove Stripe payment
```

## Getting Started

### 1. Clone the template

```bash
git clone https://github.com/ocanhdt12-gif/opencode-project-template.git my-project
cd my-project
```

### 2. Fill in your project brief

Edit `BRIEF.md` with your project idea:

```markdown
# Project Brief

## What are we building?
An order management app for small restaurants.

## Target users?
Restaurant owners and staff.

## Core features?
- Order tracking
- Menu management
- Daily reports
```

### 3. Open with your AI tool

```bash
# Opencode
opencode

# Or open the folder in Cursor / Windsurf / VS Code with Copilot
```

### 4. Let the agents work

The agent reads `AGENT.md` and starts the **Brainstorm** phase automatically. It will ask you questions one by one to clarify requirements, set up git, and select models.

## Agent Models

To avoid bias, each independent agent uses a **different model**:

| Agent | Env Var | Suggested Model |
|-------|---------|-----------------|
| Coding (main) | `CODING_MODEL` | `claude-opus-4-6` |
| Reviewer | `REVIEWER_MODEL` | `gpt-5.4` (different provider) |
| Spec Validator | `SPEC_VALIDATOR_MODEL` | `deepseek-v4-pro` (third perspective) |

These are configured in `.env.local` during the Brainstorm phase. The Brainstorm agent reads available models from your AI tool's config and presents them for you to choose.

`.env.local` is **gitignored** — your tokens and model choices are never committed.

## Git & CI/CD

### Git Setup (handled by DevOps Agent)

During brainstorm, you choose your git platform:

| Platform | Token URL |
|----------|-----------|
| **GitHub** | https://github.com/settings/tokens → scope: `repo` |
| **GitLab** | https://gitlab.com/-/user_settings/personal_access_tokens → scope: `api` |
| **Bitbucket** | https://bitbucket.org/account/settings/app-passwords → permission: `Repositories Read+Write` |

Token is saved to `.env.local` (gitignored). DevOps Agent reads it to create and push the repo.

### Branch Strategy

```
main        ← production
develop     ← staging
feature/*   ← one branch per task
```

### CI/CD Templates

DevOps Agent generates the right config based on your deploy platform:

| Platform | Generated Config |
|----------|-----------------|
| **Vercel** | `vercel.json` + GitHub Actions |
| **Railway** | `railway.toml` + GitHub Actions |
| **VPS/Docker** | `Dockerfile` + `docker-compose.yml` |
